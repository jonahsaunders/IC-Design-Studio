# Finite SKY130 MiM qualification replay candidate

This opt-in tool replays one of the 40 previously specified v1 fixtures using a separately identified source-derived AC model. It is not connected to the application simulator and makes no claim about noise, transient, arbitrary geometry or temperature, or passing the untouched original model. For the selected deterministic 27 °C / TNOM 27 °C / unit-multiplicity case, each original MiM resistor is represented by a zero-volt current sensor and a current-controlled voltage source imposing the same source-defined resistance. The original package is not changed.

Supply the fixture directory, its externally approved SHA-256, a runtime-lock JSON and its externally approved SHA-256, the simulator executable, a fresh output directory, and a case key such as `decks/p1-r0-hl/e1.cir`. The manifest must enumerate exactly the original 20 contexts and two profiles. Fixture paths are virtualized using `@FIXTURE_ASSETS@`, and every source and exact input deck is authenticated before private materialization. The runtime lock pins the simulator, initializer and library files; Linux additionally checks the actual dynamic library closure. The output includes a strict JSON receipt, private inputs, complete raw output and console log. No arbitrary caller-declared stimulus or analysis is accepted.

Invoke `replay.py` with `--fixture`, `--fixture-sha`, `--runtime`, `--runtime-sha`, `--engine`, `--output` and `--case`. Invoke `audit_pilot.py` with those parameters except `--case`, plus `--contract`, `--contract-sha`, `--replay-source` and `--replay-sha`. The independent reader reconstructs the staged bytes and deck, checks the runtime and receipt, and tests all four terminal measurements against source-defined RC equations. One pilot is not a full matrix acceptance.

`readback.py --v4-root ... --contract ... --contract-sha ...` independently checks the full retained 40-run v4 data numerically, including all six network paths and all three native fault graphs. Its result explicitly says scientific readback only; the original v4 provenance audit is separately retained. The portable code has been exercised with optimized Python (`-O`), and does not depend on assertions for validation.

The self-contained public bundle can be materialized with `build_fixture.py --bundle ... --bundle-sha ... --fixture-sha ... --output ...`. The pinned fixture and runtime identities must be approved externally. The supplied fixture is derived from the retained public-source and physical evidence, and must remain separate from the ordinary application model files. Further integration requires review of the final bytes, the independently audited full portable-matrix evidence, applicable regression checks, and preservation of the unmodified original failure record. No qualification or device-family gate is promoted by these files.
