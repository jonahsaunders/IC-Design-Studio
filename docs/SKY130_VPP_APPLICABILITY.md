# SKY130 VPP applicability checks

The public SKY130 documentation explicitly limits the magnitude of the plate
voltage difference to **0–5.5 V**: `abs(V(c0) - V(c1))`. The executable check in
`scripts/qualification_sky130_vpp_voltage.py` applies that one condition to the
nine available, exactly identified VPP model bindings in the reviewed package.
It does not establish body, shield, common-mode, temperature, lifetime or
absolute node-voltage ratings, and it does not restrict the simulator.

The [pinned upstream document](https://github.com/google/skywater-pdk/blob/7198cf647113f56041e02abf3eb623692820c5e1/docs/rules/device-details/cap_vpp/index.rst),
its original capacitance table and Apache-2.0 license are retained unchanged
under `qualification/sky130-vpp-voltage-v1/sources`. The source lock records
their revision, original paths, Git identities and complete byte digests.

The table names an `_nhv` device for the 11.3 × 11.8 µm entry. That does not
establish an alias for the unsuffixed model named by the application's source
symbol. The unsuffixed choice remains unavailable; the check rejects it.
Published capacitance values do not supply the missing fixture, body/shield
biases, temperature/frequency conditions or reliability applicability.

## Reproduce the check

Create a JSON file containing a list of points. Each point requires one exact
model name or catalog key and the two plate voltages in volts:

```json
[
  {"catalog_key": "sky130_fd_pr/vpp_cap.sym", "vc0": 5.5, "vc1": 0},
  {"catalog_key": "sky130_fd_pr/vpp_cap.sym", "vc0": 3, "vc1": -3}
]
```

```text
python scripts/qualification_sky130_vpp_voltage.py --contract docs/qualification/sky130-vpp-voltage-v1 --package icstudio/assets/pdks/sky130A --input points.json
```

The first point meets the documented plate-difference condition; the second
exceeds it. The command returns status 2 when any point is outside that
condition. Every result separately identifies the applicability dimensions
that remain unknown. Passing the differential check alone does not establish
that the selected operating point is safe or qualified.

JSON decimal coordinates are preserved exactly, including values smaller than
binary floating-point can represent. For example, `5.5000000000000000001 V`
against zero is outside the condition, not rounded down to `5.5 V`. The output
retains exact numeric coordinates and an exact signed-difference string.
Representation bounds reject excessively large numeric literals; those parser
bounds are not physical ratings. Python callers supplying floats still screen
the exact represented binary-float value.

## Descriptions and saved packages

New packages generated by `prepare_alternate_models.py` no longer copy the
default 11.5 × 11.7 µm/M5 description into every alternate VPP choice. Each
available alternate keeps its own existing source-backed M4 or M5 description.
No model bytes, pins, adjustable parameters or availability change.

The bundled package and its saved revisions remain the historical package.
Its exact reconstruction uses the explicitly named `prepare_historical`
function. To prepare a separate description-corrected copy of the current
bundled package, use a new output directory:

```text
python scripts/prepare_sky130_vpp_descriptions.py --input icstudio/assets/pdks/sky130A --output work/sky130-vpp-descriptions
```

This produces a distinct package revision with identical original assets.
It does not automatically install or promote that package, close the missing
model binding, or complete chunk 7.
